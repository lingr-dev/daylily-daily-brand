## 1. 栏目任务与核心认知

这组文章供读者长期理解萱草的定位、目标、价值和取舍，也可作为社交渠道的独立推广落点。建议采用 **四组十二篇** 的有限连载，形成可反复引用的产品解读目录。

建议整组文章围绕这一认知组织（待审的编辑命题，并非新定稿 slogan）：

> 以一个人的健康账本为中心，分清准备怎样做与实际发生了什么，保留方案变化的来路，让本人和获授权的家人有据可查。

读者读完应能回答：

1. 萱草适合什么情境，我是否需要它？
2. 健康账本里放什么，计划和记录为什么要分开？
3. 方案变化、家人协助时，哪些东西必须保持清楚？
4. 萱草愿意承担什么，以及哪些判断仍由人作出？

### 栏目名称与实施范围

栏目名称已确认采用「主张 / beliefs」，索引页标题为「萱草主张」，路径为 `/beliefs`，内容类型为 `belief_index` / `belief`。本提案沿用现有栏目承载。

目录阶段仅创建本规划；后续已按 Owner 指令完成十二篇本地短文。没有创建 CMS 条目，也没有修改导航、路由或发布站点。

## 5. 导航与连载顺序

### 固定阅读顺序

目录顺序为 01–12。每篇可单独读，并以一小段背景交代「萱草 / 健康账本」；正文后续只提供 1–2 个真正相关的延伸阅读，避免要求读者先完成整套连载。

建议索引开头设置三条简短阅读路径，以现有索引富文本承载，不新增筛选系统：

| 读者此刻的目的 | 推荐阅读 |
| --- | --- |
| 第一次认识萱草 | **02 → 03 → 10**：是什么、适合谁、承担什么 |
| 方案较复杂或正在变化 | **01 → 04 → 05 → 06**：问题、两类内容、阶段、历史 |
| 想和家人一起用 | **07 → 08 → 09**：归属、授权、日常关系 |

11、12 为愿意进一步理解设计的人提供延伸阅读。01–12 的四组划分不等同于 CMS 的 `topic`；每篇继续使用已支持的 **人群 / 意图 / 取舍 / 设计** 之一。

### 发布批次建议

| 批次 | 篇目 | 目的 |
| --- | --- | --- |
| 首批基础篇 | **01、02、03、04** | 先把问题、品类、人群与两类内容说清；02 作为长期导读入口。 |
| 第二批理解篇 | **05、06、07、08** | 解释最有区分度的变化、历史与协作设计。 |
| 第三批取舍篇 | **09、10、11、12** | 完整交代低压力体验、判断边界、便利与扩展方向。 |

这是编辑顺序，不是上线时间表。尤其 05、11 的功能描述，及涉及独立记录、协作与视图的例子，需要写作时核验实际可用状态；可以明确写为设计原则，不能把批准的概念当作现成功能。

### 长期稳定性

- 标题和 URL 不写日期、期数或 LIN 编号；序号仅用于本次编排与固定导读。
- 当前宫格按发布日期倒序排列，不具备固定分组排序。建议日后在索引引言内维护固定导读目录，下方宫格继续展示发布流；不靠虚构发布日期强行排序。本次不实现。
- 保留真实发布日期；产品事实改变时修订相关段落并说明复核日期，核心论题保持稳定。
- 正文采用「具体情境 → 面临的选择 → 产品设计 → 适用边界」结构，不绑定按钮位置、Tab 名或某一版截图。
- 能力更新归更新日志；行业热点归新闻；本栏目留给可长期成立的问题与立场。

## 7. 编辑约束与审核点

本系列的市场角度包括：工具选择与品类理解、个人自管、复杂与变化中的安排、家庭协作、低压力体验、信任与长期使用。这是编辑切入角度，不是已验证的市场分层或规模判断。

所有篇目需要区分「产品设计立场」「已批准概念」「当前已上线能力」。本轮 LIN-42 以 owner-waived 获批，不能写成目标用户已经验证、效果已经证实。场景示例应明确为示意，不伪造案例与用户评价；若后续需要点名比较竞品或引用市场数据，再单独核验当时的一手来源。

以下两个方向已获 Owner 确认，作为正文写作依据：

1. **总叙事**：是否采用「一个人的健康账本」为第一层，家庭协助与变化来路为后续展开？
2. **目录范围**：是否接受四组十二篇及各篇分工，尤其保留个人自用、模板与长期扩展这三类视角？

正文已按此范围落地，见本地文章目录；URL 仍为拟定发布路径，尚未创建远端页面。
